## 0. 프로젝트 개요

창업을 준비하는 사람들은 "이 자리가 괜찮을까?"를 알고 싶지만, 상권 데이터는 흩어져 있고 해석하기 어렵습니다. Survivo는 서울 지역 위치 하나만 입력하면 주변 유동인구 흐름, 동종업종 밀집도, 임대료 수준을 한눈에 보여주고, 이를 종합한 생존 가능성 스코어를 제공합니다. 발품 팔아 얻던 상권 정보를 누구나 30초 안에 확인할 수 있도록, 공공데이터를 시각화한 창업자용 리서치 도구입니다.

---

## 1. 배경 및 목표

### 1-1. 배경

소상공인 창업자는 입지를 결정하기 전 유동인구, 동종업종 밀집도, 임대료 수준을 각각 다른 출처에서 수집해야 한다. 공공데이터포털에 관련 데이터가 공개되어 있지만 CSV 파일을 직접 내려받아 해석해야 하는 구조여서, 비개발자에게는 사실상 접근이 어렵다. 이 프로젝트는 흩어진 3개의 공공데이터를 하나의 지도 화면으로 통합해, 서울 내 창업 예정지 입력만으로 상권 리스크를 즉시 파악할 수 있게 한다.

### 1-2. 목표

| # | 목표 | 연결 성공 기준 (→ 섹션 2) |
|---|---|---|
| G-01 | 주소 입력 후 3단계 이내에 생존 스코어 확인 가능 | 핵심 기능 도달 클릭 수 ≤ 3 |
| G-02 | 데이터 3종(상권·유동인구·임대가)을 단일 화면에서 비교 가능 | 데이터 레이어 전환 오류율 0% |
| G-03 | 포트폴리오 열람자가 30초 내 서비스 목적 이해 가능 | README + 랜딩 문구 명확성 |

### 1-3. 비목표

- **서울 외 지역** — 생활인구 데이터가 서울시 한정 제공. 1차 목표는 서울 전 행정동 커버리지. 타 지역 확장은 추후 고도화
- **실시간 데이터 갱신** — 공공데이터 업데이트 주기(연간·분기)에 맞춰 JSON 파일 수동 교체. 실시간 API 폴링 불필요
- **모바일 앱** — 웹 반응형으로 구현하되 네이티브 앱 배포는 이번 범위 밖
- **실제 임대차 중개 연결** — 정보 제공 도구이며 중개업 라이선스가 필요한 기능은 제외

> **🔲 미결정 — 배포 환경**
> 배포 플랫폼 미정. 개발 완료 후 결정 예정.

> **🔲 고도화 예정 — 회원가입·로그인**
> 1차 구현은 로컬스토리지 기반 임시 인증으로 진행. 즐겨찾기 저장·최근 검색 이력 기능과 함께 동작. 추후 필요 시 실제 백엔드 인증으로 고도화 예정.

## 3. 대상 사용자

### Primary — 창업 준비 중인 예비 소상공인

| 항목 | 내용 |
|---|---|
| 대표 유형 | 퇴직 후 또는 부업으로 카페·음식점·소매점 창업을 준비 중인 30~50대 |
| 주요 특징 | 발품을 팔아 상권을 직접 조사하지만 데이터 해석 경험은 부족함. 스마트폰·PC 모두 사용하나 복잡한 UI에 익숙하지 않음. 창업 결정 전 정보 수집 단계에서 서비스를 접함 |
| Pain Point | 유동인구·임대료·경쟁업체 수를 각각 다른 곳에서 찾아야 하고, CSV나 통계표 형태라 직접 해석하기 어려움. 컨설팅 비용은 부담스럽고 무료 정보는 산재해 있음 |
| 핵심 목표 | 특정 위치가 내 업종에 적합한지 빠르게 판단하고 싶음 |

### Secondary — 상권 데이터에 관심 있는 예비 창업 스터디·대학생

| 항목 | 내용 |
|---|---|
| 대표 유형 | 창업 동아리 또는 경영·통계 관련 수업에서 상권 분석을 과제로 수행 중인 20대 대학생 |
| 주요 특징 | 데이터 자체에 관심이 있고 PC 사용이 주. 공공데이터 존재는 알지만 직접 가공하기 번거로워 시각화 도구를 찾고 있음 |
| Pain Point | data.go.kr에서 데이터를 내려받아도 엑셀·Python 없이는 분석이 어려움 |
| 핵심 목표 | 별도 가공 없이 지역별 상권 현황을 시각적으로 비교하고 싶음 |

| 생존 스코어 카드 | 상권 밀집도·생활인구·임대가 3개 지표를 가중 합산한 스코어(0~100)와 등급(A~D) 표시 | US-02 |

- **빈 상태**: 검색 전 초기 화면에는 서울 중심부(시청) 기준 지도와 "서울 내 주소를 입력해 상권을 분석해보세요" 안내 문구 표시
- **에러 상태**: 주소 검색 결과 없을 시 "검색 결과가 없습니다. 다른 주소를 입력해주세요" 인라인 메시지 표시. 서울 외 지역 입력 시 별도 안내 메시지. 데이터 로드 실패 시 토스트 알림으로 안내

## 8. 데이터 설계

### 8-1. 데이터 소스

| 종류 | 설명 | 위치 / 키 |
|---|---|---|
| 정적 JSON | 소상공인 상가(상권)정보 — 서울 필터링 후 JSON 변환본 | `src/data/stores.json` |
| 정적 JSON | 서울 생활인구 행정동별 (최근 1개월) — JSON 변환본 | `src/data/living-population.json` |
| 정적 JSON | 한국부동산원 임대료·공실률·임대가격지수 (소규모·중대형·집합) — JSON 변환본 | `src/data/rent-small.json` 외 2종 |
| 로컬스토리지 | 최근 검색 위치 목록 (최대 5개) | `localStorage` key: `recentSearches` |
| 로컬스토리지 | 회원 정보 · 로그인 상태 (1차 구현) | `localStorage` key: `users`, `authUser` |
| 지도 API | 주소 → 좌표 변환 (카카오맵 또는 네이버지도 Geocoding API) | 개발 시 확정 |

### 8-2. 핵심 데이터 스키마

```typescript
// 상가 업소 (stores.json)
interface Store {
  id: string;           // 필수 | 상가업소번호
  name: string;         // 필수 | 상호명
  categoryMain: string; // 필수 | 업종 대분류명
  categorySub: string;  // 필수 | 업종 소분류명
  categoryCode: string; // 필수 | 업종 소분류 코드 (6자리)
  lat: number;          // 필수 | 위도
  lng: number;          // 필수 | 경도
  address: string;      // 필수 | 도로명주소
}

// 생활인구 (living-population.json)
interface LivingPopulation {
  dongCode: string;    // 필수 | 행정동 코드
  dongName: string;    // 필수 | 행정동명
  date: string;        // 필수 | 기준일 (YYYY-MM-DD)
  hour: number;        // 필수 | 시간대 (0~23)
  population: number;  // 필수 | 생활인구 수
}

// 임대 정보 (rent-[type].json)
interface RentInfo {
  region: string;       // 필수 | 권역명 (예: 서울 강남권)
  quarter: string;      // 필수 | 분기 (예: 2025-Q1)
  rentPerSqm: number;   // 필수 | ㎡당 임대료 (천원)
  vacancyRate: number;  // 필수 | 공실률 (%)
  priceIndex: number;   // 필수 | 임대가격지수
}

// 회원 정보 (localStorage: users) — 1차 구현
interface User {
  id: string;        // 필수 | UUID
  email: string;     // 필수 | 이메일 (로그인 식별자)
  password: string;  // 필수 | 단순 해시 또는 평문 (1차 구현 한계 명시)
  nickname: string;  // 필수 | 닉네임
  createdAt: string; // 필수 | ISO 8601 형식
}
```

### 8-3. 주요 함수 목록

| 함수명 | 동작 | 입력 | 반환 |
|---|---|---|---|
| `searchAddress(query)` | 지도 API Geocoding으로 주소 → 좌표 변환 | `query: string` | `{ lat: number, lng: number, label: string }` |
| `getStoresNearby(lat, lng, code, radius)` | 반경 내 동종업종 JSON 필터링 | `lat, lng, categoryCode, radius(m)` | `Store[]` |
| `getLivingPopulation(dongCode)` | 행정동 코드 기준 시간대별 생활인구 조회 | `dongCode: string` | `LivingPopulation[]` |
| `getRentData(region, type)` | 권역·상가유형 기준 임대 지표 조회 | `region: string, type: 'small' \| 'large' \| 'complex'` | `RentInfo[]` |
| `calcSurvivalScore(stores, population, rent)` | 3개 지표 가중 합산으로 생존 스코어 산출 | `stores, population, rent` | `{ score: number, grade: 'A' \| 'B' \| 'C' \| 'D' }` |
| `saveRecentSearch(location)` | 최근 검색 목록 로컬스토리지 저장 (최대 5개) | `location: { lat, lng, label }` | `void` |
| `signUp(email, password, nickname)` | 회원가입 — 로컬스토리지에 사용자 저장 | `email, password, nickname: string` | `User \| Error` |
| `login(email, password)` | 로그인 — 로컬스토리지 대조 후 인증 상태 저장 | `email, password: string` | `User \| Error` |
| `logout()` | 로그아웃 — 로컬스토리지 인증 정보 삭제 | — | `void` |

## 10. Out of Scope

| 항목 | 제외 이유 |
|---|---|
| 서울 외 지역 | 서울 생활인구 데이터가 서울시 한정.<br>  데이터 정합성을 위해 1차 목표를 서울로 제한. 추후 확장 예정 |

| 매출·수익 예측 | 실제 매출 데이터는 비공개. 공공데이터만으로 수익 예측은 신뢰도 확보 불가 |
